1 gtypes objects

For most functions in strataG, you will need to load your data into a gtypes object. A gtypes object is an R S4 class with several slots that are fully described in ?gtypes. However, unless you fully know what you are doing, it is not advised that you try to create gtypes objects or extract information from them directly. Several utility functions have been provided to make this process easier which will be described and demonstrated below.

First, let’s look at how one can read raw genetic data into R and how it should be formatted.

1.1 Genotypic Data

It is easiest to load raw genotype data from a text file, for example saved in comma-delimited (.CSV) format. The standard R functions read.table() or read.csv() can be used to accomplish this. However, in strataG, the readGenData() function has been provided for reading data from .CSV files. This is a wrapper for data.table::fread() that sets commonly used values for missing data and removes blank lines.

gen.data <- readGenData("msats.csv")
str(gen.data)

 $ id     : chr  "4495" "4496" "4498" "5814" ...
 $ D11t.1 : chr  "133" "137" "133" "135" ...
 $ D11t.2 : chr  "133" "141" "133" "139" ...
 $ EV37.1 : chr  NA NA "220" "210" ...
 $ EV37.2 : chr  NA NA "220" "226" ...

 $ EV94.2 : chr  NA "251" "265" "265" ...

Genetic data should have one column per allele at a locus. Columns for multiple alleles in the same locus (e.g., diploid data) should be next to each other and have the same column name, but differ in suffix (e.g., “Locus.1”, “Locus.2” or “LocA”, “LocB”). A column of individual identifiers should be the first column.

1.3 Stratification schemes

If desired, individuals can also be stratified to different populations. The suggested way to manage this is to create a spreadsheet that has one row per individual. The first column should contain sample identifiers. Every column thereafter specifies a stratification “scheme”. The values in each of the columns identify which stratum the individual in that row belongs to in that scheme. Multiple schemes can be defined. If some individuals are not to be involved in analyses of a given scheme, that is, they are unstratified, the value for that scheme should be left blank.

schemes <- readGenData('schemes.csv')

1.4 Creating a gtypes object (df2gtypes)

The easiest way to create a gtypes object is with the df2gtypes() function. To use this function, you have to have loaded the genetic data as a matrix or data.frame in the workspace. By default, the function assumes that the first column in the data contains the individual identifiers, the second column contains population stratifications, and third column and all columns thereafter contain allelic data.

Here is an example constructing such a data.frame with the example microsatellite data and the stratification schemes. Throughout this tutorial, we’ll use functions from the tidyverse to manipulate the data.frames:

schemes <- readGenData('schemes.csv')
gen.data <- readGenData("msats.csv")

gen.df <- schemes |> 
  select(id, region) |> 
  left_join(gen.data, by = 'id')

str(gen.df)
'data.frame':   128 obs. of  12 variables:
 $ id     : chr  "4495" "4496" "4498" "5814" ...
 $ region : chr  "Offshore.North" "Offshore.North" "Offshore.North" "Offshore.North" ...
 $ D11t.1 : chr  "133" "137" "133" "135" ...
 $ D11t.2 : chr  "133" "141" "133" "139" ...
 $ EV37.1 : chr  NA NA "220" "210" ...
 $ EV37.2 : chr  NA NA "220" "226" ...
 $ EV94.1 : chr  NA "243" "245" "251" ...
 $ EV94.2 : chr  NA "251" "265" "265" ...
 $ Ttr11.1: chr  "211" NA "209" "209" ...
 $ Ttr11.2: chr  "211" NA "211" "209" ...
 $ Ttr34.1: chr  "185" "189" "189" "185" ...
 $ Ttr34.2: chr  "191" "189" "189" "187" ...

We then create a gtypes object with this data.frame, specifying that it is diploid data (ploidy = 2).

msats.g <- df2gtypes(
  gen.df,
  ploidy = 2
)

msats.g

<<< gtypes created on 2026-11-04 18:49:43 >>>

Contents: 126 samples, 5 loci, 3 strata

Strata summary:
         stratum num.ind num.missing num.alleles
1        Coastal      68         1.2         4.8
2 Offshore.North      40         0.8        12.6
3 Offshore.South      18         0.0        11.0

Note that any individuals without data are dropped from the created gtypes object.

If you wish to restratify individuals for some analyses, you can optionally include the stratification scheme to the object when creating it by supplying the data.frame to the schemes argument. You can also include a meaningful description to the gtypes object that will get used in labelling some output:

msats.g <- df2gtypes(
  gen.df,
  ploidy = 2,
  schemes = schemes,
  description = "Example microsatellite data"
)

msats.g

<<< Example microsatellite data >>>

Contents: 126 samples, 5 loci, 3 strata
Stratification schemes: region, offshore, ecotype

Strata summary:
         stratum num.ind num.missing num.alleles
1        Coastal      68         1.2         4.8
2 Offshore.North      40         0.8        12.6
3 Offshore.South      18         0.0        11.0

Haploid data would be created in the same way:

# grab first allele of first locus to simulate haploid data

#' note that we can use pipes here to read the data directly and 
#' create a gtypes object in the same pipeline

hap.g <- readGenData('schemes.csv') |> 
  select(id, ecotype) |> 
  left_join(
    select(readGenData("msats.csv"), id, D11t.1), 
    by = 'id'
  ) |> 
  df2gtypes(
    ploidy = 1, 
    description = 'haploid example'
  )

hap.g

<<< haploid example >>>

Contents: 125 samples, 1 locus, 2 strata

Strata summary:
   stratum num.ind num.missing num.haplotypes
1  Coastal      67           0              2
2 Offshore      58           0             11

If the haplotypes are associated with sequences (e.g., mtDNA), the sequences are included in creating the gtypes object. If the sequence names are the same as the individual ids, then just replicate that column in the data.frame passed to df2gtypes (but make sure to give the new column a different name).

If haplotypes are missing in the sequences provided, an error is thrown and the gtypes object won’t be created. In this case, we also need to remove those rows before creating the object.

seq.df <- schemes |> 
  # we just need the id and strata assignments
  select(id, region) |>  
  # add a new column for the sequence ids
  mutate(dLoop = id) |>
  # remove ids without sequences
  filter(dLoop %in% names(dolph.seqs)) 

dolph.seqs <- read.fasta(
  system.file("extdata/dolph.seqs.fasta", package = "strataG")
) 

seqs.g <- df2gtypes(
  seq.df,
  ploidy = 1,
  sequences = dolph.seqs,
  schemes = schemes,
  description = 'Dolphin mtDNA sequences'
)

seqs.g

<<< Dolphin mtDNA sequences >>>

Stratification schemes: region, offshore, ecotype

Strata summary:
         stratum num.ind num.missing num.haplotypes

1.5 Creating a gtypes object directly from sequences (sequence2gtypes)

The sequence2gtypes() function creates an unstratified gtype object with just a set of DNA sequences:

seqs.g <- sequence2gtypes(dolph.seqs)
seqs.g

<<< gtypes created on 2026-11-04 18:49:44 >>>

Contents: 126 samples, 1 locus, 1 stratum

Strata summary:
  stratum num.ind num.missing num.haplotypes
1 Default     126           0            126

Sequence summary:
   locus num.seqs mean.length mean.num.ns mean.num.indels
1 gene.1      126         402           0             1.9

If you have a vector that identifies strata designations for the sequences, that can be supplied as well:

# extract the stratifications, remove unstratified individuals
eco.strata <- schemes |> 
  select(id, ecotype) |> 
  filter(!is.na(ecotype)) |> 
  deframe()

tail(eco.strata)
     78067      78068      78069      78530      78531      78532 
 "Coastal"  "Coastal"  "Coastal" "Offshore" "Offshore" "Offshore" 
# create the gtypes object
seqs.g <- sequence2gtypes(
  dolph.seqs, 
  strata = eco.strata, 
  seq.names = "dLoop",
  description = "dLoop: ecotype stratification"
)

seqs.g

2 Conversions from other packages

There are conversion functions for data objects from several other popular packages in R, such as adegenet(genind), pegas(loci), and phangorn(phydat).

library(adegenet)
# from example(df2genind)
df <- data.frame(locusA=c("11","11","12","32"),
                 locusB=c(NA,"34","55","15"),
                 locusC=c("22","22","21","22"))
row.names(df) <- .genlab("genotype",4)
obj <- df2genind(df, ploidy=2, ncode=1)

3 Accessor functions

There are several functions for getting basic information from a gtypes object (see ?accessors):

  • getNumInd(g) The number of individuals.
  • getNumLoci(g) The number of loci.
  • getNumStrata(g) The number of strata in the current scheme.
  • getIndNames(g) The names of the individuals.
  • getLociNames(g) The names of the loci or genes.
  • getStrataNames(g) The names of the strata in the current scheme.
  • getPloidy(g) The ploidy of each locus.
  • getStrata(g) The current strata to which each individual belongs.
  • getSchemes(g) A data frame of potential stratification schemes.
  • getSequences(g) The sequences stored in a haploid object.
  • getDescription(g) The text description of the object.
  • getOther(g) The list used to store other information about the object.

Some functions are available for modifying values in the object as well, such as:

  • setStrata(g) Replace the vector of strata assignments.
  • setSchemes(g) Replace the data.frame of potential stratification schemes.
  • setDescription(g) Replace the label describing the object.
  • setOther(g) Replace the optional data stored in the @other slot.

4 Subsetting/Indexing

A gtypes object can be subset using the standard R ‘[’ indexing operation, with three slots: [i, j, k]. The first (i) specifies the desired individuals, the second (j) is the loci to return, and the third (k) is the strata. All standard R indexing operations involving numerical, character, or logical vectors work for each argument.

For example, to return a gtypes object containing 5 random individuals from the example microsatellite data provided in the package:

# get 10 random ids
ran.ids <- sample(getNumInd(msats.g), 5)
head(ran.ids)
[1] 52 46  1 53 30
# index to extract
sub.msats <- msats.g[ran.ids, , ]
sub.msats

<<< Example microsatellite data >>>

Contents: 5 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype

Strata summary:
         stratum num.ind num.missing num.alleles
1        Coastal       4         0.2           3
2 Offshore.South       1         0.0           2

…or to return specific loci:

sub.msats <- sub.msats[, c("D11t", "EV37", "TV7"), ]
sub.msats

<<< Example microsatellite data >>>

Contents: 5 samples, 2 loci, 2 strata
Stratification schemes: region, offshore, ecotype

Strata summary:
         stratum num.ind num.missing num.alleles
1        Coastal       4         0.5         2.5
2 Offshore.South       1         0.0         2.0

…or some loci in a specific stratum:

sub.msats <- msats.g[, c("Ttr11", "D11t"), "Coastal"]

5 Stratifying samples

You can specify the stratification scheme when creating a gtypes object as in the examples above. Once a gtypes object has been created, you can also change the stratification scheme by either supplying a new vector for the strata slot:

# randomly stratify individuals to two populations
msats <- msats.g
new.strata <- sample(c("Pop1", "Pop2"), getNumInd(msats), rep = TRUE)
names(new.strata) <- getIndNames(msats)
setStrata(msats) <- new.strata
msats

<<< Example microsatellite data >>>

Contents: 126 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype

Strata summary:
  stratum num.ind num.missing num.alleles
1    Pop1      64         0.8          11
2    Pop2      62         1.2          13

or, if there is a stratification scheme data.frame in the schemes slot, you can use the stratify function to choose a stratification scheme:

# choose "broad" stratification scheme
msats <- stratify(msats, "ecotype")
msats

<<< Example microsatellite data >>>

Contents: 126 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype

Strata summary:
   stratum num.ind num.missing num.alleles
1  Coastal      68         1.2         4.8
2 Offshore      58         0.8        13.6

You can update the schemes with a data.frame like this:

new.schemes <- getSchemes(msats)
new.schemes$inner.outer <- sample(
  c("Inner", "Outer", NA), 
  nrow(new.schemes), 
  rep = TRUE
)
setSchemes(msats) <- new.schemes

NOTE: Filling or changing the schemes slot does not affect the current stratification of the samples. You must then select a new stratification scheme or fill the strata slot as above.

msats.inner.outer <- stratify(msats, "inner.outer")
msats.inner.outer

<<< Example microsatellite data >>>

Contents: 88 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype, inner.outer

Strata summary:
  stratum num.ind num.missing num.alleles
1   Inner      39         0.8          11
2   Outer      49         0.6          12

You can also randomly permute the current stratification scheme using the permuteStrata() function like this:

msats <- stratify(msats, "offshore")

# original
msats

<<< Example microsatellite data >>>

Contents: 58 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype, inner.outer

Strata summary:
  stratum num.ind num.missing num.alleles
1   North      40         0.8          13
2   South      18         0.0          11
# permuted
ran.msats <- permuteStrata(msats)
ran.msats

<<< Example microsatellite data >>>

Contents: 58 samples, 5 loci, 2 strata
Stratification schemes: region, offshore, ecotype, inner.outer

Strata summary:
  stratum num.ind num.missing num.alleles
1   North      40         0.8          13
2   South      18         0.0          10

NOTE: Only samples assigned to strata are permuted with permuteStrata. Those not assigned (NAs) remain unassigned.
